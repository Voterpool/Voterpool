# Бутстрап сборки на пустом хосте (build-bootstrap)

## Purpose

Контракт поведения `build.sh` на чистой машине без предустановленных зависимостей: скрипт ДОЛЖЕН самостоятельно довести хост от «только что созданная VPS» до успешного билда бинарника — установив тулчейн и системные библиотеки штатным пакетным менеджером, — независимо от того, запущен он интерактивно или в режиме `--yes`, от root или от обычного пользователя с sudo.

## Requirements

### Requirement: Первый вопрос на пустом хосте не прерывает скрипт

Скрипт ДОЛЖЕН корректно работать в интерактивном режиме (без `--yes`) на хосте, где ещё нет C++20-компилятора: обнаружив отсутствие компилятора, он ДОЛЖЕН задать пользователю вопрос об установке тулчейна и дождаться ответа, а НЕ завершаться аварийно с ошибкой shell (`unbound variable` или иной). Переменные, читаемые в диалоговых функциях, ДОЛЖНЫ иметь определённое значение при любом наборе флагов запуска.

#### Scenario: Интерактивный запуск на системе без компилятора

- **WHEN** `./build.sh` запущен на пустом Ubuntu 22.04/24.04 или Debian 12/13 без флагов, в терминале
- **THEN** после предупреждения об отсутствии компилятора скрипт выводит вопрос «установить тулчейн?» и ждёт ввода; ответ «Y» запускает установку пакетов; ошибка `unbound variable` не возникает ни на каком шаге

### Requirement: Работа под root

Скрипт ДОЛЖЕН одинаково работать при запуске от root и от обычного пользователя с sudo. Определение необходимости повышения привилегий НЕ ДОЛЖНО порождать ошибок выполнения, сообщений «command not found» или ненулевого кода возврата; при отсутствии необходимости в повышении команда установки пакетов ДОЛЖНА выполняться напрямую без префикса.

#### Scenario: Установка пакетов от root

- **WHEN** скрипт выполняет установку системных пакетов через apt-get от имени root
- **THEN** apt-get получает переменную окружения `DEBIAN_FRONTEND=noninteractive`, все пакеты устанавливаются, stderr не содержит «command not found», код возврата скрипта — 0 на этом этапе

#### Scenario: Пользователь с sudo

- **WHEN** скрипт выполняется от обычного пользователя, у которого есть sudo
- **THEN** установка пакетов выполняется через sudo и завершается успешно

### Requirement: Неинтерактивный режим доводит пустой хост до билда

Запуск `./build.sh --yes` на поддерживаемом пустом хосте ДОЛЖЕН пройти полный цикл без единого вопроса пользователю: установить тулчейн и системные библиотеки, собрать Drogon из исходников в `.deps/` (если его нет в репозиториях дистрибутива), выполнить configure и build проекта. Код возврата — 0, артефакт `build/voterpool` существует.

#### Scenario: Полный прогон CI-режима на пустой машине

- **WHEN** `./build.sh --yes` выполнен на свежесозданной VPS Ubuntu 22.04 (root, 1 CPU)
- **THEN** скрипт завершается кодом 0 без запросов ввода, бинарник `build/voterpool` создан и отвечает на запуск

### Requirement: Fail-fast для неподдерживаемых дистрибутивов

Если штатные репозитории дистрибутива заведомо не содержат требований сборки (C++20-компилятор с корутинами, cmake ≥ 3.20) — Debian ≤ 11, Ubuntu ≤ 20.04, — скрипт ДОЛЖЕН прекратить работу с понятным диагностическим сообщением (какая версия обнаружена, какие версии минимально нужны), а НЕ начинать многошаговую установку, которая заведомо не приведёт к успеху. Сообщение ДОЛЖНО содержать указание использовать поддерживаемый дистрибутив.

#### Scenario: Debian 11 отклоняется сразу

- **WHEN** `./build.sh` запущен на Debian 11 (bullseye)
- **THEN** скрипт выводит сообщение с именем и версией дистрибутива, причиной отказа и требованием Debian ≥ 12 / Ubuntu ≥ 22.04, и завершается ненулевым кодом до попытки установить пакеты

### Requirement: Подсказка при опечатке во флаге

При получении неизвестной опции скрипт ДОЛЖЕН вывести ошибку и, если существует близкий по написанию поддерживаемый флаг (например, введён `-yes` вместо `--yes`), включить эту подсказку в сообщение.

#### Scenario: Одинарная черта вместо двойной

- **WHEN** скрипт запущен с аргументом `-yes`
- **THEN** выводится «Unknown option: -yes» с подсказкой про `--yes`, код возврата ненулевой

### Requirement: Сборка на хосте с малым объёмом памяти

Перед компиляцией зависимостей из исходников и перед сборкой проекта скрипт ДОЛЖЕН проверять доступную память; если её недостаточно для линковки/компиляции при текущих джобах (типичный отказ `cc1plus killed` на 1–2 ГБ VPS), скрипт ДОЛЖЕН либо включить временные меры (swap-файл, удаляемый при завершении работы скрипта, и/или снижение числа параллельных джобов), ЛИБО явно предупредить о невозможности их применить. Смерть компилятора от OOM без предупреждения НЕ ДОПУСКАЕТСЯ как молчаливый исход.

#### Scenario: Малая VPS без swap получает временный своп и билдится

- **WHEN** `./build.sh --yes` выполнен на хосте с ~900 МБ доступной памяти и без активного swap
- **THEN** до сборки Drogon создаётся временный swap-файл, число джобов при необходимости снижено с предупреждением, по завершении скрипта (включая аварийное) swap отключён и файл удалён, билд завершается успехом

#### Scenario: swapon недоступен — деградация без блокировки

- **WHEN** создание swap невозможно (непривилегированный контейнер)
- **THEN** скрипт выводит предупреждение с причиной и продолжает билд без дополнительного swap

### Requirement: Согласие пользователя на временный swap

Создание временного swap-файла ДОЛЖНО быть согласовано с пользователем. В интерактивном режиме скрипт ДОЛЖЕН задать явный вопрос и при отказе продолжить без swap с предупреждением. В неинтерактивном режиме (`--yes`) согласие считается предданным только когда сработал триггер критической нехватки памяти; пользователь ДОЛЖЕН иметь способ полностью запретить создание swap флагом `--no-swap` независимо от режима.

#### Scenario: Интерактивный отказ

- **WHEN** триггер сработал, пользователь ответил «n» на вопрос о создании swap
- **THEN** swap не создаётся, выводится предупреждение о возможном OOM, билд продолжается

#### Scenario: Явный запрет

- **WHEN** скрипт запущен с `--no-swap` на хосте с критически малой памятью
- **THEN** вопрос не задаётся, swap не создаётся ни при каких условиях, ограничение джобов по памяти сохраняется

### Requirement: Режим --vcpkg устанавливает свои bootstrap-зависимости

В режиме vcpkg перед запуском bootstrap-скрипта vcpkg система сборки ДОЛЖНА проверить наличие его преквизитов (curl, zip, unzip, tar) и установить через системный пакетный менеджер только фактически отсутствующие. Отказ bootstrap'а со стороны отсутствующих утилит НЕ ДОЛЖЕН достигать пользователя на поддерживаемых дистрибутивах.

#### Scenario: Пустой хост без zip

- **WHEN** `./build.sh --vcpkg` выполнен на системе, где нет zip/unzip/tar
- **THEN** скрипт устанавливает недостающие утилиты пакетным менеджером и доводит bootstrap vcpkg до работоспособного состояния
