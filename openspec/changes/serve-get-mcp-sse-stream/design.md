# Design: GET /mcp keepalive SSE-поток

## Context

Спека 2026-07-28 удалила GET-stream и рекомендует 405 для серверов, поддерживающих только эту ревизию. Но клиенты ревизий 2025-* открывают standalone GET после handshake и падают на не-200 (кейс opencode: «sse error non-200 status code (405)» из пакета `eventsource`). Спека разрешает поддержку нескольких ревизий одновременно — значит, легальный путь совместимости: отвечать на GET потоком. Точка входа — регистрация маршрутов в `VoterpoolApp.cpp::registerRoutes`, образец async-SSE ответа — существующий хендлер `/mcp/events` (newAsyncStreamResponse + SseHub).

## Goals / Non-Goals

**Goals:**

- Любой клиент, открывающий `GET /mcp` (с токеном или без), получает живое SSE-соединение без ошибок.
- Нулевой приём данных: поток ничего не транслирует, кроме heartbeat-комментариев — поведение безопасно и для анонимных соединений.
- Минимальная нагрузка: один таймер/соединение, освобождение при дисконнекте.

**Non-Goals:**

- Полная легаси-транспортная семантика HTTP+SSE (событие `endpoint`, доставка JSON-RPC ответов поверх потока) — сервер отвечает на POST инлайн; фальшивый `endpoint` сломал бы такие клиентов иначе (зависание запросов).
- Server-initiated сообщения в этом потоке (sampling/elicitation/уведомления каталога) — их нет в stateless-ядре; `/mcp/events` остаётся каналом доменных событий.

## Decisions

### D1. Keepalive-only поток без события endpoint

GET /mcp → 200, `text/event-stream`, далее только строки `: ping\n\n` каждые `sse.heartbeat_interval_sec`.

*Альтернативы:* слать `event: endpoint\ndata: /mcp` — отклонено: легаси-клиент начнёт POSTить ответы-ожидания в /mcp и зависнет на каждом запросе (ответы приходят инлайн, не по потоку); оставить 405 — отклонено: воспроизводимый крэш реальных клиентов; вернуть 204/plain 200 без text/event-stream — отклонено: EventSource-клиенты требуют корректный content-type для открытия.

### D2. Анонимный доступ, токен только для логов

Поток не передаёт данных — авторизовать нечего. Валидация токена выполняется middleware как обычно, но результат НЕ влияет на открытие потока (иначе невалидный токен = снова отказ старому клиенту). agent_id из контекста пишется в лог открытия.

*Альтернатива:* требовать валидный токен как `/mcp/events` — отклонено: это канал без данных, а отказ = регресс исходной проблемы.

### D3. Реализация: per-connection таймер, общий формат с SseHub

Хендлер создаёт async-stream response; локальный механизм периодической записи кадра heartbeat (переиспользуемый helper рядом с SseHub либо общий код SseHub, если его API позволяет подписку «только heartbeat»). Закрытие: по дисконнекту клиента (drogon stream close callback), по drain/shutdown — существующая draining-логика закрывает соединения процессным выходом; отдельный graceful-close не требуется, heartbeat-интервал мал.

*Альтернатива:* единый глобальный таймер на все потоки — отклонено на этом этапе: усложняет lifecycle ради экономии микроскопических накладных расходов; вернуться при росте числа соединений (метрика покажет).

### D4. DELETE /mcp остаётся 405

SDK-клиенты толерантны к 405 на terminateSession (`streamableHttp.js`: `if (!response.ok && response.status !== 405)`). Менять нечего — фиксируем в спеке как есть.

### D5. Наблюдаемость

Счётчик `voterpool_mcp_get_streams_total{outcome="opened"}` без лейблов клиента (кардинальность); строка request-лога на открытие (method=GET, tool=-). Никаких тел/токенов в логах — дисциплина docs/11 сохраняется.

## Risks / Trade-offs

- [Долгоживущие соединения копятся] → Heartbeat закрывает мёртвые TCP через ошибку записи; drogon освобождает стрим по дисконнекту; счётчик открытых потоков даст оператору видимость.
- [Легаси HTTP+SSE клиент повиснет в ожидании endpoint-события] → Осознанно: зависание с таймаутом лучше крэша, а полная эмуляция легаси-транспорта противоречит архитектуре (D1). Современные клиенты не ждут endpoint.
- [Прокси буферизуют SSE] → Heartbeat-кадры и `text/event-stream` без сжатия — та же модель, что уже работает для `/mcp/events` (docs/06).

## Migration Plan

Обратная совместимость полная: POST-поведение не меняется, 405→200 меняет только GET-ветку, которой раньше завершались ошибкой. Rollback — откат бинарника. После деплоя старый opencode подключается без обновления.
