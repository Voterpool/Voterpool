# Fix: сборка на пустом хосте (build.sh)

## Why

`./build.sh` на чистой VPS не работает: скрипт спроектирован сам ставить зависимости, но три ошибки в shell-коде убивают его до начала установки. Реальный сценарий владельца VPS (root@ubuntu-22.04, `./build.sh`) завершается ошибкой `NONINTERACTIVE: unbound variable`, затем после `--yes` — `DEBIAN_FRONTEND=noninteractive: command not found`, и пакеты так и не ставятся. README обещает «определит дистрибутив, поставит зависимости, соберёт» — обещание не выполняется.

## What Changes

- Исправить три дефекта в `build.sh`, из-за которых автоустановка зависимостей не выполняется:
  - переменная `NONINTERACTIVE` используется до инициализации (`set -u` роняет скрипт при первом интерактивном вопросе);
  - root-ветка `sudo_cmd()` содержит голый литерал `""`, который bash пытается исполнить как команду (exit 127);
  - конструкция `$s DEBIAN_FRONTEND=noninteractive apt-get install ...` ломается при пустом `$s` (root): bash трактует присваивание как имя команды — пакеты не устанавливаются.
- Добавить fail-fast для дистрибутивов, чьи штатные репозитории не содержат C++20-тулчейн (Debian ≤ 11, Ubuntu ≤ 20.04): понятное сообщение с конкретикой вместо каскада малопонятных ошибок посреди установки.
- Мелкий UX: при неизвестном флаге вида `-yes` подсказывать ближайший корректный вариант (`--yes`).
- OOM-гард для малых VPS (реальный кейс `cc1plus killed` при сборке Drogon): временный swap-файл 2 ГБ с очисткой по выходу + ограничение джобов по доступной памяти.
- Режим `--vcpkg` доустанавливает bootstrap-преквизиты vcpkg (curl/zip/unzip/tar) перед bootstrap'ом (реальный кейс: `Could not find zip` на пустой Ubuntu).
- Гард интерактивного режима: запуск без терминала и без `--yes` даёт явную ошибку вместо молчаливого ответа «Y».

Поддерживаемая матрица «пустой хост → успешный билд»: Ubuntu 22.04/24.04 и Debian 12/13 (x86_64), запуск от root или от пользователя с sudo, интерактивно и с `--yes`. Debian 11 и старее — вне скоупа (осознанно, см. дизайн).

## Capabilities

### New Capabilities
- `build-bootstrap`: контракт поведения `build.sh` на пустом хосте — автоустановка тулчейна и системных библиотек, работа под root и sudo-пользователем, интерактивный и неинтерактивный режимы, диагностика неподдерживаемых дистрибутивов.

## Impact

- Код: только `build.sh` (~110 строк: 4 точечных фикса, гейт версий, OOM-гард с swap-жизненным циклом, `pm_install`-рефакторинг, преквизиты vcpkg).
- Не затрагивается: CMakeLists.txt, исходники проекта, vcpkg.json, CI-пайплайны (CI уже использует `--yes` от не-root пользователя и работает).
- Риски минимальны: правки локальны; отказ swap-механизма деградирует в предупреждение; проверяются прогоном в Docker-контейнерах `ubuntu:22.04`, `ubuntu:24.04`, `debian:12` от root (вынесено в отдельную задачу верификации).
