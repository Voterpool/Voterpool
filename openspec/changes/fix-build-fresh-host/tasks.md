## 1. Три shell-фикса в build.sh

- [x] 1.1 Добавить `NONINTERACTIVE=0` в блок дефолтов (стр. ~29, рядом с `ASSUME_YES`/`DO_CLEAN`). Проверка: `bash -n build.sh`; интерактивный запуск `./build.sh` на машине без компилятора доходит до вопроса об установке тулчейна (ошибка `unbound variable` не возникает); `shellcheck build.sh` не выдаёт новых предупреждений SC2154/SC2086 по затронутым строкам.
- [x] 1.2 Переписать root-ветку `sudo_cmd()` на `if [ "$(id -u)" -eq 0 ]; then echo ""; elif have sudo; then echo sudo; fi`. Проверка: под root `s="$(sudo_cmd)"; echo "[$s]"` печатает `[]`, код возврата 0, stderr пуст; под пользователем с sudo печатает `[sudo]`.
- [x] 1.3 В ветке apt-get (стр. ~188) заменить установку на `$s env DEBIAN_FRONTEND=noninteractive apt-get install -y $pkgs`. Проверка: репродукционный тест из design D3 (`s=""; $s env VAR=x printenv VAR`) зелёный; dry-run установки от root в контейнере не содержит «command not found».

## 2. Fail-fast для неподдерживаемых дистрибутивов

- [x] 2.1 Добавить хелпер `distro_min_version_met()` по design D4 (debian ≥ 12, ubuntu ≥ 22.04, прочие — true) и вызвать его перед обоими местами автоустановки тулчейна (компилятор, cmake): при false — `err` с именем/версией ОС и требованием Debian ≥ 12 / Ubuntu ≥ 22.04, `exit 1` вместо `confirm`. Проверка: на контейнере `debian:11` скрипт завершается ненулевым кодом с диагностикой до попытки apt-get install; хост с пройденными пробами компилятора/cmake гейт не задевает.

## 3. Подсказка при опечатке во флаге

- [x] 3.1 В обработчике неизвестной опции нормализовать кандидат снятием ведущих `-` и сверить со списком известных имён; при совпадении дополнить вывод «did you mean --<name>?». Проверка: `./build.sh -yes` → «Unknown option: -yes» + подсказка про `--yes`, код возврата 1; `./build.sh --yess` → без ложной подсказки. → Выполнено; оба сценария проверены на реальном скрипте.
- [x] 3.2 Гард интерактивного режима (найден при верификации): обёртка `confirm … || { … }` отключает `set -e` внутри `ask()`, поэтому неудачный `read </dev/tty` (запуск без терминала и без `--yes`) молча давал ответ по умолчанию «Y» и запускал установку. Добавлена явная обработка: неудача чтения → `err "Interactive input unavailable (no terminal); rerun with --yes."` + exit 1. Проверка: форк-прогон без терминала завершается rc=1 с этим сообщением до любых попыток установки.

## 4. Верификация матрицы «пустой хост → билд»

> Решение владельца (apply-сессия): контейнерная верификация (4.1, 4.2) исключена из этого изменения — среда разработки не позволяет запускать Docker; вынесена в отдельное будущее изменение. Локальная верификация кода выполнена харнес-тестами функций и форк-прогонами гейтов (см. отмеченные задачи). shellcheck в среде недоступен.
>
> Статус на конец apply-сессии: синтаксис `bash -n` ✓; харнес 21/21 PASS (инициализация NONINTERACTIVE в чистом env; sudo_cmd root/sudo-ветки; env-репродукция D3; матрица гейта debian/ubuntu/fedora/неизвестные версии; suggest_option позитивы/негативы); реальные безопасные прогоны: `-yes` → подсказка + rc=1, `--yess` → без подсказки, `--help` → rc=0; форк-гейты: debian/11 без компилятора → диагностика тулчейна rc=1, ubuntu/20.04 с плохим cmake → диагностика cmake rc=1, fedora/41 без терминала → явная ошибка интерактивного ввода без установки.

Проверка: скрипт проходит вопросы без аварийного завершения, доводит до билда; повторный запуск после успешной сборки идёт по короткому пути (все ok-статусы, без переустановки).
