## MODIFIED Requirements

### Requirement: Грациозное завершение

По SIGTERM/SIGINT движок ДОЛЖЕН выполнить последовательность: прекратить принимать новые HTTP/MCP соединения → асинхронно закрыть все SSE-стримы кадром server_shutdown → запросить остановку воркеров (TTL завершает текущую итерацию; диспетчер дренирует очередь) → синхронно сбросить memtable хранилища на диск и корректно закрыть базу → сбросить буферы асинхронного логгера → завершиться с кодом 0. Прекращение приёма ДОЛЖНО выполняться draining-флагом, включаемым обработчиком сигнала первым делом: каждый новый POST /mcp, пришедший после сигнала, ДОЛЖЕН мгновенно отклоняться ответом HTTP 503 без диспетчеризации и обращения к хранилищу; эндпоинты GET /health и GET /metrics ДОЛЖНЫ оставаться доступными до выхода процесса (балансировщики снимают инстанс по /health после его перевода в недоступность или по факту завершения). Повторный сигнал во время процедуры остановки ДОЛЖЕН быть безопасным (идемпотентным).

#### Scenario: SIGTERM завершает с кодом 0

- **WHEN** работающему движку отправляется SIGTERM при активных SSE-подписках
- **THEN** клиенты получают кадр server_shutdown, данные сброшены на диск, процесс завершается кодом 0

#### Scenario: Новые запросы отклоняются в draining-режиме

- **WHEN** POST /mcp приходит после получения сигнала остановки, но до выхода процесса
- **THEN** запрос немедленно получает HTTP 503 без обработки MCP-сообщения; GET /health продолжает отвечать

#### Scenario: Повторные сигналы безопасны

- **WHEN** SIGTERM приходит во время уже идущей процедуры остановки
- **THEN** завершение остаётся корректным без повреждения данных
