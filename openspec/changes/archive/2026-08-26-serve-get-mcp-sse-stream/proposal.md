# GET /mcp как keepalive SSE-поток для старых клиентов

## Why

Ревизия MCP 2026-07-28 удалила GET-stream, и сервер отвечает на `GET /mcp` кодом 405 (спека это рекомендует). Но реальные клиенты эпохи 2025-03-26…2025-11-25 открывают standalone GET-поток после успешного handshake и считают любой не-200 фатальной ошибкой: подтверждённый кейс — opencode с bundled SDK, который после трёх успешных `initialize` падает с «sse error non-200 status code (405)» из fallback-транспорта (пакет `eventsource`, `EventSource.js: failConnection("Non-200 status code ...")`). Каждый пользователь старого харнесса воспроизводит отказ без всякой вины сервера.

## What Changes

- **GET /mcp** вместо 405 отвечает `200 OK`, `Content-Type: text/event-stream` и держит соединение открытым: только heartbeat-комментарии (`: ping`) раз в `sse.heartbeat_interval_sec`, ни одного события/сообщения — сервер не имеет server-initiated данных.
- Доступ анонимный разрешён (поток ничего не передаёт); при наличии валидного Authorization агент резолвится для логов, невалидный токен НЕ рвёт поток.
- Событие `endpoint` сознательно НЕ посылается: оно включило бы легаси HTTP+SSE семантику (ответы поверх потока), которую сервер не реализует; клиент, ждущий `endpoint`, получит таймаут вместо крэша — приемлемая деградация для древнего транспорта.
- **DELETE /mcp** остаётся `405 Method Not Allowed` (SDK-клиенты толерантны к 405 на terminate).
- Дельта спеки mcp-protocol (требование «Методы HTTP эндпоинта /mcp»), обновление docs/05 §1.0.2, e2e-тесты.

Не меняется: POST-обработка, initialize/handshake, `/mcp/events`, диспетчеризация, авторизация инструментов.

## Capabilities

### New Capabilities

_(нет)_

### Modified Capabilities

- `mcp-protocol`: требование «Методы HTTP эндпоинта /mcp» — GET /mcp теперь открывает молчащий keepalive SSE-поток (совместимость с клиентами ревизий 2025-*), DELETE сохраняет 405.

## Impact

- Код: `src/server/VoterpoolApp.cpp` (GET-хендлер /mcp с async-SSE ответом по образцу `/mcp/events`), возможно небольшой helper рядом с SseHub; метрика открытия потока.
- Тесты: `tests/e2e/test_protocol.cpp` (GET → 200 + text/event-stream + heartbeat; DELETE → 405; расширенный handshake-сценарий), регресс существующих suite'ов.
- Docs: `docs/05-mcp-contracts.md` §1.0.2 (замена пункта про 405), README упоминание совместимости не требует правок (формулировки уже общие).
- Риски: рост числа долгоживущих соединений — митигируется heartbeat-интервалом, закрытием по дисконнекту и drain-логикой; кардинальность метрик не страдает (счётчик без лейблов клиента).
