# Delta: data-persistence

## MODIFIED Requirements

### Requirement: Неизменяемый журнал аудита

Каждое административное или консенсусное изменение (смена силы, активация участника, передача админа, правка метаданных организации, смена конфига) ДОЛЖНО записываться в append-only журнал аудита ТЕМ ЖЕ атомарным пакетом, что и сама мутация («нет действия без аудита»). Записи журнала НИКОГДА не удаляются, включая роспуск организации, и ДОЛЖНЫ читаться по организации в хронологическом порядке. Ключ каждой записи ДОЛЖЕН быть уникален при любом числе событий в одной миллисекунде и при любых перезапусках процесса: никакая запись НЕ ДОЛЖНА перезаписываться или теряться из-за коллизии ключа (в том числе при циклическом счётчике последовательности или повторном использовании счётчика после рестарта); порядок чтения ДОЛЖЕН быть хронологическим вплоть до записей одной миллисекунды, созданных одним запуском процесса.

#### Scenario: Аудит следует за действием

- **WHEN** ADMIN меняет voting_power участника
- **THEN** в журнале появляется запись POWER_CHANGED со старым/новым значением и инициатором, неотделимая от самой мутации

#### Scenario: История переживает роспуск

- **WHEN** организация распущена, затем запрашивается её история аудита
- **THEN** все записи сохранены и читаемы

#### Scenario: Более 1000 событий за одну миллисекунду

- **WHEN** для одной организации записано 1500 аудито-событий с одинаковым временем (одна миллисекунда)
- **THEN** все 1500 записей присутствуют в журнале и читаемы, ни одна не была перезаписана последующими

#### Scenario: Перезапуск не создаёт коллизий

- **WHEN** процесс остановлен и запущен заново, затем новые события попадают в ту же миллисекунду, что и события до остановки
- **THEN** ранее записанные события остаются неизменными и читаемыми; новые записи добавлены рядом, суммарное число записей равно числу событий

#### Scenario: Хронологический порядок внутри одной миллисекунды

- **WHEN** несколько событий одной организации одного запуска процесса имеют одинаковую миллисекунду
- **THEN** listByOrg возвращает их в порядке создания (лексикографический порядок ключей совпадает со временем записи)

### Requirement: Бэкапы через согласованные снапшоты

CLI-команда `voterpool checkpoint --config <path> --path <dir>` ДОЛЖНА создавать согласованный point-in-time снимок средствами механизма checkpoints хранилища на живой БД, работать offline (воркеры и HTTP не поднимаются), завершаться кодом 0 при успехе / 1 при ошибке (stderr). Команда ОБЯЗАНА отказываться снимать копию больной базы (не открылась или corruption). При работающем на том же пути движке команда ДОЛЖНА получить ошибку блокировки. Снимок ДОЛЖЕН фиксировать данные КАК ЕСТЬ на момент выполнения: команда НЕ ДОЛЖНА выполнять миграции схемы или иные логические мутации исходной базы — версия схемы и содержимое записей источника после команды совпадают с состоянием до неё; снимок ДОЛЖЕН быть возможен независимо от соотношения версии схемы базы и бинарника. Развёрнутый из снимка каталог ДОЛЖЕН открываться движком со всеми читаемыми данными и штатно проходить процедуру миграций при более новом бинарнике.

#### Scenario: Снимок остановленного движка

- **WHEN** `voterpool checkpoint` выполняется на остановленном движке
- **THEN** создаётся согласованный каталог-снимок, процесс завершается с кодом 0

#### Scenario: Отказ на деградировавшей базе

- **WHEN** база повреждена (corruption)
- **THEN** checkpoint отказывает с ошибкой и кодом 1, снимок не создаётся

#### Scenario: Восстановление из снимка

- **WHEN** содержимое снимка развёрнуто в новую директорию хранилища и движок запущен
- **THEN** база открывается, все данные читаемы, состояние соответствует моменту снимка

#### Scenario: Снимок старой схемы новым бинарником не мигрирует источник

- **WHEN** `voterpool checkpoint` выполняется текущим бинарником над базой с версией схемы ниже его собственной
- **THEN** команда завершается кодом 0; версия схемы и записи исходной базы не изменены (миграция не выполнялась); развёрнутый из снимка каталог открывается движком и проходит цепочку миграций до текущей версии на копии
