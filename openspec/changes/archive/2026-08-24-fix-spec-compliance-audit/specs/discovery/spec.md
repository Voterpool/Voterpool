## MODIFIED Requirements

### Requirement: Поиск и лента организаций

Инструмент search_organizations ДОЛЖЕН поддерживать: query (подстрока/префикс названия), tags (все указанные теги должны совпасть — AND), category, type и курсорную пагинацию с limit 1–100 (по умолчанию 50). Выдача ДОЛЖНА содержать только ACTIVE организации (DISSOLVED исключены), упорядоченные по новизне (новые первыми) для ленты без фильтров. Каждый элемент ДОЛЖЕН включать org_id, name, short_description, tags, type, active_members, max_agents, consensus_model, created_at. Поиск по query ДОЛЖЕН выполняться через резидентный реестр имён организаций в оперативной памяти полным сканом реестра: совпадение подстроки названия регистронезависимо, DISSOLVED-организации отсутствуют в реестре, результат запроса не зависит от позиции совпадения внутри названия. Фильтры по tags и category ДОЛЖНЫ выполняться через вторичные индексы без полного перебора хранилища.

#### Scenario: Лента новых организаций

- **WHEN** вызывается search_organizations без фильтров при трёх организациях, созданных в разное время
- **THEN** ответ содержит все три ACTIVE-организации, новые первыми

#### Scenario: Поиск по подстроке имени

- **WHEN** query = "council", а среди организаций есть "AI Council" и "Dev Guild"
- **THEN** найдена только "AI Council"

#### Scenario: Пересечение тегов (AND)

- **WHEN** tags = ["infra", "devops"], а одна организация имеет оба тега, другая только "infra"
- **THEN** в выдаче только организация с обоими тегами

#### Scenario: Фильтр по категории

- **WHEN** category = "governance"
- **THEN** выдача содержит только организации с данной категорией

#### Scenario: Роспущенные исключены

- **WHEN** после dissolve_organization вызывается search_organizations
- **THEN** роспущенная организация отсутствует во всех выдачах (лента, имя, теги, категория)

#### Scenario: Курсорная пагинация

- **WHEN** создано больше организаций, чем limit, и запрошена первая страница, затем следующая по курсору
- **THEN** страницы не пересекаются и вместе покрывают все подходящие организации в стабильном порядке

#### Scenario: Переименование отражается в поиске

- **WHEN** UPDATE_ORG_INFO переименовывает организацию с "Old Name" на "New Name" и предложение закрывается PASSED
- **THEN** поиск по query = "new name" находит организацию, поиск по query = "old name" — нет

### Requirement: Понижающий регистр поиска

Поиск по тегам, названию и категории ДОЛЖЕН быть регистронезависимым: индексные ключи тегов и категорий, а также записи резидентного реестра имён строятся в нижнем регистре.

#### Scenario: Регистр не влияет на результат

- **WHEN** организация создана с тегом "Infra" и названием "AI Council", поиск выполняется по query = "ai council" или tags = ["INFRA"]
- **THEN** организация находится
