# Fix spec compliance audit

## Why

Аудит соответствия specs↔код выявил 5 подтверждённых дефектов: три сценария спецификаций провалены кодом (PENDING-членства невидимы в `get_agent`; поиск по имени не находит подстроку; частичная `config_delta` молча подменяет конфигурацию организации дефолтами), один нарушает честность наблюдаемых данных (карточка `get_proposal` и метрика `voterpool_actions_applied_total` сообщают о применении действия, которого не было), один — гарантированный crash при опциональном флаге восстановления индекса (`rebuild_index_on_start` разыменовывает nullptr).

## What Changes

- **get_agent видит PENDING**: обратный индекс `cf_agent_orgs` пишется при любом статусе членства (сейчас — только при ACTIVE), поэтому профиль агента показывает и ACTIVE, и PENDING членства, как требует agent-identity.
- **Поиск по подстроке через резидентный реестр имён** (**BREAKING** для внутренней механики поиска): при старте движка все `(org_id, name_lower)` организаций загружаются в память; `search_organizations` с query сканирует этот реестр полным перебором в памяти (подход «full in-memory scan»), а не префиксный Seek по RocksDB-индексу. Реестр также обслуживает проверку дубликата имени в `create_organization`. Точность 100% для подстроки; RocksDB остаётся источником истины.
- **config_delta мержится поверх текущей конфигурации**: отсутствующие поля наследуются от действующего конфига организации (не от дефолтов); CONSENT/SHARES-валидация и применение выполняются к смерженному итогу. Частичная дельта `{power_distribution: SHARES}` в CONSENT-орге → -32005; частичная дельта больше не подменяет consensus_model/quorum/duration молча.
- **Исход применения хранится на предложении**: `Proposal` получает поля `config_delta_applied` и `action_applied`, проставляемые в момент финализации; `get_proposal` читает сохранённые значения вместо деривации из `PASSED + наличие`. Метрика `voterpool_actions_applied_total` инкрементируется только при фактическом применении действия. Обратная совместимость старых записей НЕ поддерживается (отсутствующее поле = false).
- **Чинится crash `rebuild_index_on_start`**: репозитории конструируются до блока восстановления индекса активных предложений.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `discovery`: требование «Поиск и лента организаций» — механизм поиска по названию меняется с вторичного RocksDB-индекса на резидентный in-memory реестр имён с полным сканом памяти (гарантия подстроки без ограничения scanned-ключей).
- `organizations`: требование «Создание организации» — фиксируется семантика частичной дельты: `config_delta` наследует отсутствующие поля из текущей конфигурации организации, валидация и применение — к смерженному итогу.
- `mcp-protocol`: требование «Инструмент get_proposal» — признаки `action_applied` / `config_delta_applied` отражают фактически применённые эффекты, сохранённые при закрытии предложения (не выводятся из статуса PASSED).

Примечание: фиксы #1 (`agent-identity`) и #5 (`background-workers`) приводят код в соответствие с уже существующими требованиями — дельты требований не нужны, изменение чисто кодовое (+тесты).

## Impact

- **Код**: `OrgRepository.cpp` (индекс членств), `IndexRepository.{h,cpp}` + новый резидентный реестр имён, `SearchOrganizations.cpp`, `CreateOrg.cpp`, `ConsensusEngine.cpp` (мерж-валидация точки применения, флаги исхода, порядок метрики), `ToolHelpers.h`/`CreateProposal.cpp` (parseOrgConfig с базой), `Codec.h` (сериализация флагов Proposal), `GetProposal.cpp`, `AppContext.cpp` (порядок инициализации), `Proposal.h`.
- **Тесты**: новые integration/unit кейсы на все 5 дефектов (~12 сценариев), включая пограничные; прогон полного набора unit/integration/e2e зелёным.
- **Совместимость**: целевое поведение без миграции старых данных; у записанных до фикса предложений флаги исхода считаются false.
- **Docs**: после реализации синхронизировать README (разделы поиска) и docs/ по итогам архивации change.
