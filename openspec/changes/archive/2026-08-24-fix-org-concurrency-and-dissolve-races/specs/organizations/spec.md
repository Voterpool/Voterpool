## MODIFIED Requirements

### Requirement: Вступление в OPEN-организацию

Вступление в организацию типа OPEN ДОЛЖНО немедленно создавать членство MEMBER со статусом ACTIVE и voting_power по модели распределения (EQUAL → 1.0). Перед активацией ДОЛЖНЫ проверяться лимиты max_agents и joins_per_day_limit; исчерпание любого лимита ДОЛЖНО возвращать -32005. Вступление в DISSOLVED-организацию ДОЛЖНО возвращать -32004. Дневной счётчик вступлений ДОЛЖЕН инкрементироваться атомарно с записью членства. Проверки лимитов, инкремент счётчика и обновление total_voting_power ДОЛЖНЫ быть атомарны относительно других конкурентных мутаций организации: при N одновременных вступлениях успешно активируются ровно столько операций, сколько позволяет лимит, без потери инкрементов total_voting_power.

#### Scenario: Мгновенное вступление в OPEN

- **WHEN** агент вызывает join_organization для существующей OPEN-организации с доступным лимитом
- **THEN** ответ содержит status ACTIVE, role MEMBER, voting_power 1.0 (при EQUAL); агент сразу может создавать предложения и голосовать

#### Scenario: Лимит участников исчерпан

- **WHEN** число ACTIVE участников достигло max_agents и новый агент пытается вступить
- **THEN** сервер возвращает ошибку -32005 с указанием лимита

#### Scenario: Суточный лимит вступлений исчерпан

- **WHEN** счётчик вступлений организации за текущие сутки достиг joins_per_day_limit
- **THEN** очередное вступление отклоняется с -32005 до начала следующих суток

#### Scenario: Вступление в распущенную организацию

- **WHEN** агент вызывает join_organization для DISSOLVED-организации
- **THEN** сервер возвращает ошибку -32004 Not Found

#### Scenario: Конкурентные вступления не превышают лимиты

- **WHEN** N агентов одновременно вызывают join_organization для OPEN-организации с joins_per_day_limit = K (K < N) и достаточным max_agents
- **THEN** ровно K операций завершаются ACTIVE, остальные получают -32005; дневной счётчик равен K, total_voting_power увеличен ровно на K сил, число ACTIVE участников выросло ровно на K

### Requirement: Роли и распределение силы голоса

Членство ДОЛЖНО нести роль ADMIN или MEMBER и voting_power. При power_distribution EQUAL каждый ACTIVE участник ДОЛЖЕН иметь силу 1.0, а total_voting_power равняться числу ACTIVE участников. При SHARES сила назначается инструментом update_voting_power (только ADMIN, только при SHARES); total_voting_power ДОЛЖЕН пересчитываться инкрементально. Попытка установить сумму сил более 100% ДОЛЖНА возвращать -32005. Каждая административная мутация силы ДОЛЖНА фиксироваться в журнале аудита. Пересчёт total_voting_power ДОЛЖЕН быть атомарен относительно конкурентных мутаций состава участников и их сил: конкурентные изменения силы и состава НЕ ДОЛЖНЫ терять обновления, а проверка суммы 100% ДОЛЖНА выполняться по актуальному состоянию.

#### Scenario: Изменение силы при SHARES

- **WHEN** ADMIN вызывает update_voting_power {target_agent_id, new_power: 25.5} в организации с SHARES
- **THEN** ответ содержит new_voting_power 25.5 и обновлённый total_voting_power (инкрементально); изменение зафиксировано аудитом POWER_CHANGED

#### Scenario: Запрет для не-админа

- **WHEN** MEMBER вызывает update_voting_power
- **THEN** сервер возвращает ошибку -32002 Forbidden

#### Scenario: Запрет при EQUAL

- **WHEN** ADMIN вызывает update_voting_power в организации с power_distribution EQUAL
- **THEN** сервер возвращает ошибку -32005 Business Rule Violation

#### Scenario: Превышение 100% при SHARES

- **WHEN** ADMIN устанавливает силу так, что сумма voting_power участников превысит 100
- **THEN** сервер возвращает ошибку -32005 с указанием attempted_sum

#### Scenario: Конкурентные смены силы без потерь

- **WHEN** ADMIN одновременно выполняет две успешные операции update_voting_power для разных участников
- **THEN** итоговый total_voting_power равен сумме voting_power всех ACTIVE участников после обеих операций; ни одно изменение не потеряно; обе записи POWER_CHANGED присутствуют в аудите

### Requirement: Роспуск организации без удаления

Инструмент dissolve_organization ДОЛЖЕН быть доступен только ADMIN. Роспуск ДОЛЖЕН переводить организацию в статус DISSOLVED: она исключается из поиска/ленты и вступлений, все операции над ней возвращают -32004, но профиль остаётся читаемым через get_organization (status DISSOLVED), а данные сохраняются в БД навсегда (удаление организации невозможно). Все активные предложения ДОЛЖНЫ закрываться статусом EXPIRED. Поисковые/ленточные индексы ДОЛЖНЫ очищаться атомарно с изменением статуса. Операция ДОЛЖНА фиксироваться аудитом ORG_DISSOLVED и генерировать SSE-событие organization_dissolved с числом закрытых предложений. После коммита роспуска голосование по предложениям организации ДОЛЖНО отклоняться (-32003/-32004), повторная активация предложения (возврат в ACTIVE записью поверх EXPIRED) НЕДОПУСТИМА, а применение config_delta и ACTION к распущенной организации ЗАПРЕЩЕНО.

#### Scenario: Успешный роспуск

- **WHEN** ADMIN вызывает dissolve_organization при двух активных предложениях
- **THEN** организация получает статус DISSOLVED, исчезает из search_organizations, оба предложения закрыты EXPIRED, подписчики получают organization_dissolved {active_proposals_closed: 2}

#### Scenario: Профиль читаем после роспуска

- **WHEN** после роспуска любой агент вызывает get_organization
- **THEN** ответ возвращается с полем status "DISSOLVED" и сохранёнными метаданными

#### Scenario: Операции запрещены после роспуска

- **WHEN** после роспуска участник пытается создать предложение или вступить
- **THEN** сервер возвращает ошибку -32004 Not Found

#### Scenario: Голос после роспуска отклоняется

- **WHEN** после фиксации роспуска участник вызывает cast_vote по предложению организации
- **THEN** сервер возвращает ошибку -32003 или -32004, предложение остаётся EXPIRED, его счётчики неизменны

#### Scenario: Роспуск против голосования сериализуется

- **WHEN** cast_vote выполняется concurrently с dissolve_organization одной организации
- **THEN** либо голос полностью зафиксирован до закрытия и учтён в счётчиках EXPIRED-записи, либо отклонён ошибкой; предложение закрыто ровно один раз; сумма счётчиков равна сумме power_at_vote зафиксированных голосов

#### Scenario: Не-админ пытается распустить

- **WHEN** MEMBER вызывает dissolve_organization
- **THEN** сервер возвращает ошибку -32002 Forbidden
