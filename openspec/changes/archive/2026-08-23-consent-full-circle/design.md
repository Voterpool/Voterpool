# Design: Полный круг согласия в модели CONSENT

## Context

Текущая реализация `ConsentModel::evaluate` (include/consensus/IConsensusModel.h) закрывает предложение PASSED при первом «ЗА» без «ПРОТИВ». Спецификация (openspec/specs/consensus-engine) и docs/02 §1.4.3 описывают именно это поведение, поэтому правка затрагивает код, спеку и документацию одновременно. Движок уже вызывает `evaluate()` после каждого `cast_vote` под пер-предложенческим локом; TTL-воркер вызывает финальный `evaluate(p, true)`. У `Proposal` есть замороженная `total_voting_power_at_creation` (T) и счётчик `voters_count`; числа участников-«голов» в записи нет. `OrgRepository::countActiveMembers()` уже существует. Мотивация и принятые решения — в proposal.md.

## Goals / Non-Goals

**Goals:**
- PASSED модели CONSENT только при полном круге: `voters_count ≥ H` ∧ `yes_power > 0` ∧ `no_power == 0`.
- EXPIRED по таймауту при любом незавершённом круге (включая частичную явку с «ЗА»).
- Замороженный `eligible_voters_at_creation` (H) в записи Proposal, сквозная сериализация.
- Запрет CONSENT+SHARES на всех путях конфигурирования (create_organization, config_delta).
- Видимость H для агентов через get_proposals / get_proposal.
- Синхронная правка docs/00, 01, 02, 05, 10 и спек consensus-engine + organizations.

**Non-Goals:**
- Миграция хранилища (решение 4: legacy-записи с H = 0 живут по старому правилу).
- Цикл «возражение → доработка предложения → новый круг» из полной социократии (REJECTED остаётся финальным; автор переопубликовывает предложение).
- Учёт голосов строго «участников эпохи создания» (решение 2: принято упрощение `C ≥ H`).
- Изменение моделей MAJORITY / QUORUM_PERCENTAGE и их Early-Exit.

## Decisions

1. **Мера полноты круга — головы, а не сила.** Альтернатива «V ≥ T по замороженной силе» отвергнута: голоса вступивших после создания участников выводят V за пределы T и дают ложный ранний PASS; нулевые силы при SHARES невидимы для V. Подсчёт голов соответствует и формулировке docs/02 («кворум в головах»), и социократической семантике. Хранится целочисленное `eligible_voters_at_creation` — без float-сравнений.
2. **Порядок правил evaluate (CONSENT):** `no_power > ε → REJECTED`; затем `yes_power > ε ∧ voters_count ≥ H → PASSED`; затем `timeExpired → EXPIRED`; иначе ACTIVE. REJECTED по первому NO сохраняется как единственный Early-Exit — при N = 0 прохождение остаётся достижимым до конца круга, отдельное условие недостижимости (как в MAJORITY/QUORUM) не требуется.
3. **H снимается в CreateProposal** вызовом `countActiveMembers(org_id)` и пишется в запись предложения одним батчем. Создатель входит в H и обязан голосовать наравне со всеми (в органе из одного участника круг замыкается его голосом).
4. **Валидация CONSENT ⇒ EQUAL — в `parseOrgConfig`** (ToolHelpers.h): единая точка для create_organization и config_delta; ошибка -32005 Business Rule Violation. Альтернатива «только документировать» отвергнута: без валидации конфиг противоречил бы документации, а переключение SHARES→CONSENT через дельту порождало бы невзвешиваемые «головы».
5. **Дефолт декода H = 0 без миграции** (решение 4): `C ≥ 0` воспроизводит прежнее поведение для записей старого чекпоинта. Осознанно принято: проект до релиза, поле опционально в JSON-кодеке.
6. **API:** `get_proposals` и `get_proposal` добавляют поле `eligible_voters_at_creation` (обратно совместимо). SSE-события не расширяются — прогресс круга читается опросом.
7. **Документация правится синхронно:** docs/02 (§1.1.1 семантика вариантов, §1.2.2 ограничение SHARES, §1.4.3 новая формула с H, §1.5 краевые случаи: новички, H = 0, отсутствие zero-power-кейса для CONSENT), docs/01 (схема Proposal), docs/00 (формула модели), docs/05 (контракты), docs/10 (матрица исходов для тестов).

## Risks / Trade-offs

- [Новички, голосующие по старому предложению, «закрывают круг» вместо промолчавших ветеранов] → принято как известное упрощение (решение 2), задокументировано в спеке и docs/02 §1.5; при необходимости позже вводится снапшот состава.
- [Восстановленный старый чекпоинт с H = 0 снова допускает PASS с первого «ЗА»] → принято (решение 4); поведение совпадает с прежней семантикой, данные не портятся.
- [Существующие тесты, где один голос YES закрывал CONSENT-предложение] → обновляются: в органе из одного участника поведение не меняется (H = 1), в многоучастнических флоу добавляются голоса до полного круга.
- [Двойная запись H и T при создании] → обе константы пишутся в одном WriteBatch; расхождение невозможно без отказа коммита целиком.
- [Полномочный ADMIN переключает модель на CONSENT при активных предложениях] → активные предложения продолжают считаться по `config_at_creation` (уже гарантировано движком); новые предложения требуют полного круга.

## Migration Plan

1. Деплой новой версии; старые чекпоинты читаются без конверсии (H = 0).
2. Активные на момент деплоя предложения, восстановленные из чекпоинта, ведут себя по legacy-правилу; новые предложения создаются уже с H.
3. Откат — возврат предыдущей версии: поле `eligible_voters_at_creation` в JSON просто игнорируется старым декодером.
