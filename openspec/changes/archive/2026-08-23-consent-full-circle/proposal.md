# Proposal: Полный круг согласия в модели CONSENT

## Why

Модель CONSENT сейчас принимает предложение в момент первого голоса «ЗА» (`yes_power > 0 && no_power == 0`) — это противоречит референсу консента из социократии: решение должно приниматься только после завершения полного круга согласия, когда проголосовали все участники, возражений нет и есть хотя бы одно явное «ЗА». Молчание участников сегодня ошибочно эквивалентно согласию.

## What Changes

- **BREAKING** Семантика PASSED модели CONSENT: закрытие предложения происходит не при первом «ЗА», а когда `voters_count ≥ H`, где `H = eligible_voters_at_creation` — замороженное при создании число ACTIVE-участников; требуется `no_power == 0`, `yes_power > 0` и полный круг.
- **BREAKING** Таймаут при неполном круге (даже если есть «ЗА» и нет «ПРОТИВ») завершает предложение статусом EXPIRED (неявка ≠ согласие).
- Новое замороженное поле `Proposal.eligible_voters_at_creation` (снимается через `countActiveMembers()` при create_proposal; сериализуется в Codec; декодируется с дефолтом 0).
- Валидация конфигурации: сочетание `consensus_model = CONSENT` с `power_distribution = SHARES` отклоняется ошибкой -32005 при create_organization и при config_delta — для консента все голоса равны, вариант SHARES отсутствует.
- API `get_proposals` / `get_proposal` возвращают `eligible_voters_at_creation`, чтобы агенты видели прогресс круга.
- Обратная совместимость хранилища: старые записи Proposal без поля декодируются с `H = 0`; правило `C ≥ 0` сохраняет прежнее поведение (первое «ЗА» проходит) — миграция не требуется, поведение принимается как известное наследие.
- Синхронная правка документации: docs/00, docs/01, docs/02 (§1.1.1, §1.2.2, §1.4.3, §1.5), docs/05, docs/10.

Принятые решения (зафиксированы пользователем):
1. Таймаут при частичной явке с «ЗА» и без «ПРОТИВ» → EXPIRED.
2. Голоса вступивших во время голосования увеличивают `voters_count`; правило `C ≥ H` — известное упрощение, документируется.
3. Для CONSENT варианта SHARES нет — все голоса равны; фиксируется документацией и валидацией.
4. Миграция хранилища не нужна: legacy-записи с `H = 0` работают по старому правилу.

## Capabilities

### New Capabilities

_(нет)_

### Modified Capabilities

- `consensus-engine`: переписано требование «Модель CONSENT (отсутствие возражений)» — полный круг, EXPIRED при неполной явке; требование «Создание предложения» дополняется фиксацией `eligible_voters_at_creation`; требование «Замороженная сумма сил T» дополняется заморозкой H; сценарий «Голос нулевой силы» заменён сценарием валидации EQUAL.
- `organizations`: требование create_organization/config_delta дополняется ограничением `CONSENT ⇒ power_distribution = EQUAL` (-32005).

## Impact

- Код: `include/consensus/IConsensusModel.h` (ConsentModel::evaluate), `include/domain/Proposal.h`, `src/mcp/tools/CreateProposal.cpp`, `include/storage/Codec.h`, `include/mcp/tools/ToolHelpers.h` (parseOrgConfig), `src/mcp/tools/GetProposals.cpp`, `src/mcp/tools/GetProposal.cpp`.
- Тесты: `tests/unit/test_consensus_models.cpp` (переписать 4 CONSENT-теста), новые интеграционные тесты полного круга/таймаута/валидации; существующие e2e/integration на CONSENT проверяются на совместимость.
- Контракты: состав ответов get_proposals/get_proposal расширен одним полем (обратно совместимо); ошибка -32005 на новое сочетание конфигурации.
- Хранилище: формат записи Proposal расширяется опциональным полем; чекпоинты старого формата читаются корректно (дефолт 0).
