## MODIFIED Requirements

### Requirement: Создание предложения

Инструмент create_proposal ДОЛЖЕН быть доступен любому ACTIVE участнику организации и принимать org_id, title, description и ровно одно из: config_delta ИЛИ action. Оба одновременно → -32005; неизвестный action.kind или payload вне схемы → -32602. Система ОБЯЗНА вычислять expires_at = created_at + voting_duration_sec из текущего конфига организации, инициализировать счётчики (yes_power, no_power, abstain_power = 0, voters_count = 0), зафиксировать total_voting_power_at_creation = T как НЕИЗМЕННУЮ константу предложения и зафиксировать eligible_voters_at_creation = H как НЕИЗМЕННОЕ число ACTIVE участников организации на момент создания. Ответ ДОЛЖЕН содержать proposal_id, status ACTIVE, created_at, expires_at. Успешное создание ДОЛЖНО генерировать SSE-событие proposal_created.

#### Scenario: Стандартное предложение

- **WHEN** ACTIVE участник создаёт предложение без config_delta/action
- **THEN** создаётся запись со статусом ACTIVE, expires_at = now + voting_duration_sec, замороженная T равна сумме сил участников на момент создания, замороженный H равен числу ACTIVE участников на момент создания; подписчики получают proposal_created

#### Scenario: Оба поля заданы

- **WHEN** create_proposal передаёт и config_delta, и action
- **THEN** сервер возвращает ошибку -32005 «Only one of config_delta or action is allowed per proposal»

#### Scenario: Не-участник создаёт предложение

- **WHEN** агент не состоит в организации (или PENDING) и вызывает create_proposal
- **THEN** сервер возвращает ошибку -32002 Forbidden

### Requirement: Модель CONSENT (отсутствие возражений)

Модель CONSENT ДОЛЖНА допускать варианты голоса {YES, NO, ABSTAIN} («за», «против», «нейтрально») по образцу консента из социократии: возражение любого участника блокирует решение, а молчание не считается согласием. PASSED ДОЛЖЕН достигаться только при полном круге согласия: voters_count ≥ H И yes_power > 0 И no_power == 0, где H = eligible_voters_at_creation (замороженное число ACTIVE участников на момент создания). Появление любого NO ДОЛЖНО немедленно закрывать предложение REJECTED (до истечения времени). По истечении времени при незавершённом круге (voters_count < H), включая нулевую явку и случай «все воздержались» (no_power == 0 И yes_power == 0), предложение ДОЛЖНО закрываться EXPIRED: неявка не трактуется ни как согласие, ни как возражение. ABSTAIN ДОЛЖЕН увеличивать voters_count, но не силы. Голоса вступивших во время голосования участников ДОЛЖНЫ учитываться в voters_count (правило voters_count ≥ H — известное упрощение, задокументированное в docs/02 §1.5). Для организаций с моделью CONSENT power_distribution SHARES НЕ ДОЛЖЕН допускаться: все голоса равны (валидация -32005, см. organizations).

#### Scenario: Первый «ЗА» не закрывает предложение

- **WHEN** в организации с тремя ACTIVE участниками (CONSENT) первый участник голосует YES
- **THEN** предложение остаётся ACTIVE: круг не завершён (voters_count = 1 < H = 3)

#### Scenario: Консент достигнут

- **WHEN** все H участников проголосовали: один YES, остальные ABSTAIN, NO отсутствует
- **THEN** на последнем голосе предложение немедленно закрывается PASSED

#### Scenario: Единственное возражение

- **WHEN** любой участник голосует NO
- **THEN** предложение немедленно закрывается REJECTED независимо от полноты круга

#### Scenario: Таймаут при частичной явке с «ЗА» без «ПРОТИВ»

- **WHEN** время истекло, есть голос YES, нет голосов NO, но voters_count < H
- **THEN** предложение закрывается EXPIRED (неявка не является согласием)

#### Scenario: Все воздержались к таймеру

- **WHEN** время истекло, есть только ABSTAIN-голоса (N = 0, Y = 0)
- **THEN** предложение закрывается EXPIRED (нет ни одного «ЗА»)

#### Scenario: Голос нулевой силы

- **WHEN** конфигурация организации сочетает consensus_model CONSENT с power_distribution SHARES (единственный источник голосов нулевой/неравной силы для CONSENT)
- **THEN** такая конфигурация отклоняется ошибкой -32005 при create_organization и config_delta: все голоса в консенте равны, кейс нулевой силы в CONSENT невозможен

#### Scenario: Одиночный круг

- **WHEN** в организации один ACTIVE участник, он голосует YES
- **THEN** предложение немедленно закрывается PASSED (voters_count = 1 ≥ H = 1)

### Requirement: Замороженная сумма сил T

Сумма total_voting_power_at_creation (T) и число ACTIVE участников eligible_voters_at_creation (H) ДОЛЖНЫ фиксироваться при создании предложения и оставаться константами до его закрытия; вступление новых участников во время голосования НЕ ДОЛЖНО менять пороги действующих предложений (только будущих). Голоса вступивших после создания участников ДОЛЖНЫ приниматься и учитываться в voters_count действующего предложения.

#### Scenario: Вступление во время голосования не меняет порог

- **WHEN** после создания предложения (T = 100, H = 3) в организацию вступает новый участник, затем голосование завершается
- **THEN** консенсус вычисляется от замороженных T = 100 и H = 3, а новый участник влияет только на T и H следующих предложений
