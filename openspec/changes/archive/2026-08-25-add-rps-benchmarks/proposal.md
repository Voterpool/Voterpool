# Proposal: add-rps-benchmarks

## Why

docs/00 фиксирует NFR-1 как численную планку («> 50 000 cast_vote/сек на одном ядре»), которая никогда не измерялась: бенчмарка пропускной способности не существует — есть только `tests/bench/hot_path_bench.cpp` с перцентилями задержки однопоточного инпроцессного диспетчера. Недоказуемая планка в документе хуже отсутствия планки, а инструмента, которым её можно было бы проверить (или снять), нет вообще.

## What Changes

- **docs/00 §5, NFR-1**: убрать численную планку RPS; требование переформулируется качественно — «максимально высокая достижимая пропускная способность», количественная оценка — дело бенчмарков, а не спеки. Архитектурные пояснения (агрегированная нагрузка, per-proposal mutex, групповой коммит WAL) сохраняются — на них опираются docs/01 §5 и дизайн-решения.
- **Новый бенчмарк-таргет `voterpool_bench`** (`tests/bench/voterpool_bench.cpp`, EXCLUDE_FROM_ALL): один бинарник, два сценария через CLI-аргумент:
  - `read` — конкурентный инпроцесс dispatch повторяемых операций (get_proposal / search_organizations / дубликат cast_vote → -32003); чистый CPU-bound потолок движка без влияния диска;
  - `write` — слив конечного пула слотов голосования (агент × предложение) успешным cast_vote с sync-WAL записью; fsync-bound пол; `--threads 1` даёт «RPS на ядро при sync WAL».
- **Дефолты скромные**, прогон по умолчанию ~10 секунд; длительные нагрузочные прогоны возможны флагами (--agents/--proposals/--threads/--duration) на отдельной машине и только по явному указанию.
- **docs/10**: обновить §3.3 и карту покрытия (строка про NFR-1) под фактический таргет и файлы вместо обещанного ранее `bench/voterpool_bench.cpp`-в-одиночку.

Не меняется: продуктовый код ядра, конфигурация, rate limiting (остаётся неактивным), существующий `hot_path_bench`.

## Capabilities

### New Capabilities

- `benchmarking`: контракт бенчмарка пропускной способности — таргет сборки, сценарии read/write, форма рабочей нагрузки (фиксированный пул слотов), формат вывода (одна JSON-строка), политика запуска (вне дефолтного ctest, скромные дефолты, явная команда для нагрузочных прогонов).

## Impact

- Новые файлы: `tests/bench/voterpool_bench.cpp`; правки `tests/CMakeLists.txt` (таргет `voterpool_bench`, EXCLUDE_FROM_ALL).
- Документы: `docs/00-initial-prd.md` (NFR-1), `docs/10-testing.md` (§3.3, карта покрытия). Ссылки на NFR-1 без числа в docs/01 остаются валидными.
- Спеки OpenSpec: без изменений (планка в openspec/specs отсутствует).
- Риск интерпретации: числа RPS зависят от железа и диска; бенчмарк обязан отчуждаемо печатать контекст прогона (потоки, слоты, setup-время), чтобы сравнивать прогоны между машинами.
