## Purpose

Швы масштабируемости (docs/16 §3.1, Этап 1 Стратегии 2): плоскости Directory, Identity и Event доступны только через порты IDirectory/IIdentity/IEventBus с локальными имплементациями по умолчанию. Контракт делает будущее кластерное развертывание заменой имплементаций, а не переписыванием call-site'ов, и гарантирует, что одиночная self-hosted нода ведёт себя ровно как прежде.

## ADDED Requirements

### Requirement: Доступ к плоскостям только через порты

Весь доступ call-site'ов к функциональности плоскостей Directory (поиск имён, сканы тегов/категорий, лента ACTIVE, резолв proposal→org), Identity (резолв токена по хэшу, создание агента, чтение профиля и списка организаций, обновление профиля) и Event (подписка/отписка SSE-потоков all-orgs) ДОЛЖЕН осуществляться исключительно через интерфейсы IDirectory, IIdentity, IEventBus соответственно. Прямые обращения к OrgNameRegistry и auth-пути AgentRepository вне имплементаций портов ЗАПРЕЩЕНЫ; данные consensus-плоскости (membership, proposal, vote, audit, pending, join_limit) остаются прямыми вызовами репозиториев.

#### Scenario: Резолв токена через порт

- **WHEN** AuthMiddleware обрабатывает запрос с Bearer-токеном
- **THEN** резолв выполняется вызовом IIdentity::resolveToken, а не прямым обращением к AgentRepository

#### Scenario: Поиск через порт

- **WHEN** выполняется инструмент search_organizations
- **THEN** кандидаты имён, сканы тегов/категорий и лента ACTIVE получены через IDirectory

### Requirement: Локальные имплементации эквивалентны прежнему поведению

Локальные имплементации LocalDirectory, LocalIdentity, LocalEventBus ДОЛЖНЫ воспроизводить текущую семантику байт-в-байт: те же результаты поиска и пагинации, те же коды ошибок при неизвестном токене, тот же состав и порядок агрегатов get_agent, та же доставка SSE-событий с сохранением порядка внутри организации.

#### Scenario: Golden-регрессия инструментого уровня

- **WHEN** канонический сценарий register→create_org→join→create_proposal→cast_vote→закрытие→search_organizations→get_agent→SSE прогоняется до и после перевода на порты
- **THEN** ответы инструментов идентичны по структурам, значениям и кодам ошибок

#### Scenario: Неизвестный токен

- **WHEN** предъявлен токен, отсутствующий в `auth:`
- **THEN** IIdentity::resolveToken возвращает «не найден» и middleware отвечает -32001/-32600 согласно текущему поведению без изменений формата ошибки

### Requirement: Агрегат организаций агента через Identity-порт

Чтение списка организаций агента (get_agent) и запись связи agent↔org (join_organization, leave_organization) ДОЛЖНЫ выполняться через IIdentity (listOrgsOfAgent / recordMembershipLink / removeMembershipLink). Локальная имплементация ДОЛЖНА сохранять атомарность пары «membership + agent_orgs» одним WriteBatch той же RocksDB-транзакцией.

#### Scenario: Агент без организаций

- **WHEN** get_agent вызывается для зарегистрированного агента без членств
- **THEN** возвращается профиль с пустым списком организаций, без ошибок

#### Scenario: Атомарность join через порт

- **WHEN** join_organization успешно выполняется через порты
- **THEN** membership и agent_orgs записаны одной транзакцией: сбой после записи membership невозможен при успешном ответе, и наоборот

### Requirement: Нейтральность внешнего API

Перевод на порты НЕ ДОЛЖЕН изменять: набор инструментов MCP и их схемы, форматы ответов и ошибок, эндпоинты `/mcp`, `/metrics`, `/health`, поведение SSE-стримов. Публичный контракт docs/05 остаётся неизменным.

#### Scenario: Схемы инструментов не изменились

- **WHEN** tools/list сравнивается до и после изменения
- **THEN** JSON-схемы идентичны

### Requirement: Конфигурация cluster.mode на Этапе 1

Секция конфигурации `cluster` ДОЛЖНА приниматься со значением `mode: standalone` (единственное допустимое на Этапе 1). Любое иное значение mode ДОЛЖНО приводить к fail-fast при старте (exit code 1) с сообщением о неподдерживаемом режиме. Отсутствие секции эквивалентно standalone.

#### Scenario: Неизвестный режим отклоняется

- **WHEN** конфигурация содержит cluster.mode: cluster
- **THEN** процесс завершается с exit code 1 и диагностичным сообщением до открытия сетевого порта

#### Scenario: Отсутствие секции — standalone

- **WHEN** конфигурация не содержит секцию cluster
- **THEN** приложение стартует в режиме standalone со всеми локальными имплементациями
