## Context

docs/16 v2.0.0 §3.1 фиксирует целевую архитектуру швов: плоскости Directory/Identity/Event за портами, локальные имплементации по умолчанию. Текущие точки прямого доступа перечислены в proposal (AuthMiddleware → AgentRepository; SearchOrganizations → OrgNameRegistry + IndexRepository сканы; AgentProfile → listOrgsOfAgent; SseHub — подписки). См. proposal.md «Why».

## Goals / Non-Goals

**Goals:**
- Порты как единственная точка доступа к трём плоскостям; компилятор гарантирует отсутствие обходных путей.
- Нулевое изменение внешнего поведения, подтверждённое golden-регрессией.
- Контрактные тесты портов, пригодные для будущих Remote-имплов (Этап 3) без переписывания тестов.

**Non-Goals:**
- Удалённые имплементации, gRPC, карта бакетов, репликация — Этап 3 / change `add-bucket-keyspace` соответственно.
- Рефакторинг consensus-plane репозиториев.
- Оптимизация производительности сверх порога регрессии <2% p99.

## Decisions

### D1. Расположение и форма портов

`include/scaling/{IDirectory,IIdentity,IEventBus}.h` — чистые абстрактные интерфейсы (виртуальный деструктор, без shared_ptr в сигнатурах где возможно), реализация `src/scaling/local/*.cpp`. Выбор каталога `scaling/` (не `core/`): самостоятельная плоскость кода, видная в дереве docs/09. Альтернатива — std::function-колбэки: отклонена (нет типизированного контракта, хуже тестируемость).

### D2. Состав интерфейсов — минимально достаточный

IDirectory: matchName(query)→set<org_id>; scanTag(t); scanCategory(c); scanFeedActive(); resolveProposal(proposal_id)→optional<org_id>. IIdentity: resolveToken(hash); createAgent(...); getProfile(agent); updateProfile(...); listOrgsOfAgent(agent); recordMembershipLink(org, agent); removeMembershipLink(org, agent). IEventBus: subscribeAllOrgs(agent, sink); unsubscribe(handle). Всё сверх этого — YAGNI до Этапа 3.

### D3. Атомарность join/leave остаётся локальной

recordMembershipLink/removeMembershipLink принимают ссылку на WriteBatch консенсусной транзакции join'а (или выполняют собственный атомарный батч, когда вызываются вне org-транзакции). Локально оба ключа в одной RocksDB — инвариант спеки сохраняется. Саги для cluster-режима фиксируются как открытое решение Этапа 3 (docs/16 §7).

### D4. Внедрение зависимостей

AppContext создаёт Local* имплы после инициализации репозиториев и держит их в unique_ptr полях; инструменты получают ссылки через ToolContext как сейчас. Конфиг: `cluster.mode` парсится Config'ом; значение != standalone → ошибка конфигурации (существующий fail-fast путь exit 1). Альтернатива — фабрика портов с реестром имплов: отклонена до Этапа 3 как преждевременная.

### D5. Стратегия тестирования

Три уровня: (1) контрактные тесты портов против Local*-имплов И фейков (один и тот же набор сценариев — параметризованный fixture), включая edge-кейсы: неизвестный токен, агент без оргов, пустой каталог, дублирующийся createAgent, конкурентные recordMembershipLink (thread-safety, tsan-прогон); (2) golden-регрессия инструментого уровня — канонический сценарий из спеки прогоняется на pre-change бинарнике (зафиксированные эталонные ответы коммитятся как fixture JSON) и после перевода; сравнение структур и кодов ошибок; (3) полный существующий suite зелёный + tools/list schema snapshot. Бенчмарк p99 до/после на cast_vote-пути (порог <2%).

## Risks / Trade-offs

- [Порты окажутся шире/уже потребностей Этапа 3] → минимальный состав D2 пересматривается дёшево: добавление метода к интерфейсу обратно совместимо для локальных имплов.
- [Виртуальные вызовы замедлят горячий путь] → cast_vote идёт через IDirectory::resolveProposal только один раз на запрос; бенчмарк-гейт в tasks; при превышении порога — devirtualize точечным кэшем резолва, не отказом от порта.
- [Обход портов новым кодом] → контрактный тест-grep в CI-задаче: файлы вне src/scaling не содержат обращений к OrgNameRegistry/auth-методам AgentRepository (статическая проверка скриптом).
- [Golden-fixture устареет при легитимном изменении формата] → процедура обновления fixture отдельной задачей с ревью diff.

## Migration Plan

Greenfield-слой поверх существующего кода: порты+имплы добавляются, call-site'ы переключаются серией малых правок, каждая зелёная в тестах. Откат — revert серии; схема БД не затрагивается вовсе. После мержа поведение неотличимо — деплой стандартный (замена бинарника).
